# 3x-ui-autodeploy

Один скрипт поднимает небольшой VPN-сервис на чистом VPS. Внутри панель [3x-ui](https://github.com/MHSanaei/3x-ui) и три способа подключения: **VLESS + Reality**, **VLESS + XHTTP + Reality** и **Hysteria2**, а в клиентах Happ, INCY и v2RayTun ещё и сервер **«⚡ Лучший сервер»**, который сам выбирает лучший протокол. У каждого пользователя своя подписка с лимитом трафика, сроком действия и, при желании, лимитом устройств. Всем управляет консольная утилита `vpn`. Домен не нужен.

- ОС: Ubuntu 24.04 (Debian 12 тоже должен работать), чистый сервер, root.
- Ресурсы: от 1 vCPU и 1–2 ГБ RAM.
- Проверено с 3x-ui **v3.9.0** (Xray 26.9.30).

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh)
```

## 1. Что получится

| Сервер | Порт | Что это |
| --- | --- | --- |
| **VLESS TCP** | 443/tcp | VLESS + Reality + Vision. Основной: для DPI выглядит как HTTPS-соединение с обычным сайтом |
| **VLESS XHTTP** | 8443/tcp | VLESS + XHTTP + Reality. Изнутри похож на HTTP/2-трафик браузера, лучше переносит «заморозку» TCP |
| **Hysteria2** | 443/udp | QUIC. Быстрый на плохих каналах, не работает там, где режут UDP |

При установке можно выбрать один или несколько серверов (HTTP3 в этот список входит только вместе со своим доменом, см. [раздел 9](#сервер-http3-vpn-http3-когда-глушат-tcp)) ([параметр `PROTOCOLS`](#параметры), без него скрипт спросит в терминале). Остальные добавляются позже командами `vpn xhttp on`, `vpn http3 on`. Все серверы крутятся в одном процессе Xray и друг другу не мешают. Плюс в подписке есть **«⚡ Лучший сервер»** ([раздел 9а](#9а-сервер-лучший-сервер)): это не отдельный сервер, а балансировщик, который сам пингует все три протокола и ведёт трафик через лучший. У каждого пользователя **одна ссылка-подписка**, в ней все серверы сразу. Клиент обновляет её раз в 6 часов и показывает остаток трафика и дату окончания. Когда трафик или срок кончается, пользователь отключается сам, сразу на всех серверах.

| Порт | Для чего |
| --- | --- |
| 443/tcp, 443/udp | VLESS TCP и Hysteria2 |
| 8443/tcp | VLESS XHTTP (можно другой или выключить) |
| случайный 20000–60000/tcp | веб-панель (с секретным путём) |
| случайный 20000–60000/tcp | раздача подписок |
| 80/tcp | выпуск и продление сертификата Let's Encrypt |
| UDP 20000–50000 | только если включён port hopping (выключен по умолчанию) |
| SSH-порт | доступ к серверу |

## 2. Подготовка

1. **Фаервол в кабинете хостера**, если он там есть. Откройте 22/tcp (или ваш SSH-порт), 80/tcp, 443/tcp, **443/udp**, 8443/tcp и 20000–60000/tcp. Если не хотите открывать весь диапазон, задайте порты сами (параметры ниже).
2. **Вход по SSH-ключу** (желательно): `ssh-copy-id root@IP`.

Остальное скрипт проверяет сам. Если что-то не так, он останавливается и пишет, что исправить.

## 3. Установка

```bash
ssh root@IP
bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh)
```

Установка занимает 3–5 минут. Если SSH может оборваться, запускайте внутри `tmux`.

### Параметры

Указываются перед командой, например `SUB_TITLE="Мой VPN" SUPPORT_URL=@admin bash <(curl ...)`:

| Параметр | Что делает |
| --- | --- |
| `PANEL_PORT`, `SUB_PORT` | свои порты панели и подписок вместо случайных |
| `PROTOCOLS=vless,hy2,xhttp` | какие серверы создать: `vless` (VLESS TCP + Reality, 443/tcp), `hy2` (Hysteria2, 443/udp), `xhttp` (VLESS XHTTP + Reality, 8443/tcp), `http3` (VLESS XHTTP по HTTP/3, 4443/udp; **нужен свой домен**, см. `SELF_DOMAIN`, и ещё `vless` или `xhttp`). Можно один или несколько, номера `1 2 3 4` тоже подходят. Если не задан, скрипт покажет меню (Enter — первые три) |
| `SELF_DOMAIN=cdn.example.com` | свой домен (A-запись должна указывать на сервер): Reality получает SNI = домен и сайт-заглушку с сертификатом Let's Encrypt, как после `vpn reality self`. **Обязателен для `http3`**, для остальных протоколов необязателен |
| `XHTTP_PORT=8443` | порт сервера VLESS XHTTP (`0` — не создавать) |
| `HOP_PORTS=20000-50000` | сразу включить port hopping для Hysteria2 (по умолчанию выключен, см. [раздел 9](#9-xhttp-и-port-hopping-когда-оператор-режет-подключения)) |
| `FASTEST=0` | не создавать сервер «⚡ Лучший сервер» (по умолчанию создаётся) |
| `REALITY_TARGET=www.site.com:443` | свой сайт для маскировки Reality вместо автоподбора |
| `DOMAIN=vpn.example.com` | сертификат на домен вместо IP (A-запись уже должна указывать на сервер) |
| `SUB_TITLE="Мой VPN"` | название подписки в клиентах (по умолчанию `VPN`) |
| `SUB_ANNOUNCE="Привет, {{EMAIL}}\nПоддержка 24/7"` | описание под подпиской |
| `SUPPORT_URL=@username` | кнопка «Поддержка» (`@username` в Telegram или ссылка) |
| `TG_BOT_TOKEN=…` + `TG_ADMIN_ID=…` | Telegram-бот 3x-ui: уведомления и бэкапы |
| `ACME_EMAIL=you@mail` | e-mail для Let's Encrypt |
| `NO_FIREWALL=1` | не настраивать ufw |
| `SKIP_EXTERNAL_CHECK=1` | не проверять порты снаружи через check-host.net |
| `ASSUME_YES=1` | на все вопросы отвечать «да» (установка без участия человека) |

### Что делает скрипт

1. **Проверяет сервер**: ОС, архитектуру, виртуализацию, RAM (от 1 ГБ), диск (от 2 ГБ), поддержку AES-NI. Если 3x-ui уже стоит, предлагает сделать бэкап и переустановить. Проверяет, что порты 80/tcp, 443/tcp и 443/udp свободны.
2. **Готовит систему**: ставит пакеты, создаёт swap на 1 ГБ, включает BBR и проверяет, что он заработал. Синхронизирует время и сверяет его с точным: если часы расходятся больше чем на 30 секунд, Reality и сертификаты не работают.
3. **Проверяет сеть**: DNS, доступ к GitHub и Let's Encrypt, внешний IP. Предупреждает, если сервер за NAT.
4. **Определяет страну сервера**: из неё получаются названия серверов вида «🇳🇱 Нидерланды · VLESS».
5. **Настраивает ufw**: SSH (порт находит сам), 80, порты панели и подписок, а также порты выбранных серверов (443/tcp, 443/udp, XHTTP).
6. **Проверяет порты снаружи** через check-host.net с узлов в России и Европе, временно подняв на портах заглушки:
   - 443 закрыт → скрипт останавливается;
   - 80 закрыт → предупреждает, что сертификат будет самоподписанным;
   - порт XHTTP закрыт → XHTTP не создаётся;
   - из Европы порт доступен, а из России нет → предупреждает, что IP, похоже, заблокирован в РФ.
7. **Ставит 3x-ui v3.9.0** и получает сертификат Let's Encrypt на IP. Сертификат живёт 6 дней и продлевается сам. Скрипт проверяет, что сертификат выдан и cron для продления создан.
8. **Подбирает маскировку Reality в сети хостера** (подробнее в [разделе 8](#8-маскировка-reality)).
9. **Создаёт выбранные серверы** (по умолчанию VLESS TCP, Hysteria2, VLESS XHTTP) и, если их два и больше, балансировщик «⚡ Лучший сервер». Настраивает подписки по HTTPS, ставит утилиту `vpn`, создаёт вашего пользователя `me` без лимитов.
10. **Проверяет всё целиком** командой `vpn check`. Проверяются сервисы, порты, ufw, время, сертификат, подписка и маскировка. Затем идёт сквозной тест: на сервере поднимается клиент, подключается по каждому протоколу и выходит через VPN в интернет. В конце порты ещё раз проверяются снаружи. Отчёт сохраняется в `/etc/vpn/check-install.txt`.

В конце скрипт выводит итог проверки, адрес панели, логин, пароль, вашу подписку и QR-код. Лог установщика 3x-ui лежит в `/var/log/vpn-setup-xui.log`.

## 4. Клиенты и подключение

| Устройство | Клиенты |
| --- | --- |
| Android | Happ, INCY, v2RayTun, Hiddify |
| iPhone / iPad | Happ, v2RayTun, Hiddify |
| Windows | v2rayN, Happ, Hiddify |
| macOS | Happ, Hiddify |
| Роутер OpenWrt | Podkop, Tachyon и другие на sing-box |

Не все клиенты умеют всё:

| | VLESS TCP | Hysteria2 | VLESS XHTTP | «⚡ Лучший сервер» | ID устройства для лимита |
| --- | --- | --- | --- | --- | --- |
| Happ, INCY, v2RayTun | да | да | да | да | передают |
| v2rayN | да | да | да | — | — |
| Клиенты на sing-box (Hiddify, Podkop, Tachyon) | да | да | **нет**, сервер просто не показывается | нет, у них свой url test | **не передают** |

**Как подключиться:** выполните `vpn link me`, затем в клиенте нажмите «+» и выберите «Импорт из буфера» или «Сканировать QR». Проверьте каждый сервер, лучше из двух сетей: мобильного интернета и домашнего провайдера. Удобнее всего поставить в клиенте автовыбор (url test, «Лучший сервер»): если какой-то сервер зарежут, клиент сам переключится на живой.

## 5. Пользователи

```
vpn add vasya 100 30 "оплатил 11.10"  # 100 ГБ на 30 дней, выводит ссылку и QR
vpn list                              # трафик, лимиты, сроки, лимиты устройств/IP
vpn link vasya                        # показать ссылку ещё раз
vpn renew vasya 30                    # +30 дней и обнулить трафик
vpn renew vasya 0 150                 # срок тот же, новый лимит трафика 150 ГБ
vpn reset vasya                       # только обнулить трафик
vpn off vasya / vpn on vasya          # отключить / включить
vpn del vasya                         # удалить (ссылка перестанет работать)
```

- `0` ГБ означает без лимита трафика, `0` дней — бессрочно, гигабайты можно указывать дробно (`0.5`).
- Имя пользователя: латиница, цифры, `. _ - @`, до 64 символов.
- `renew` продлевает от текущей даты окончания, если она ещё не наступила, иначе от сегодняшнего дня.
- Если пользователь не продлил подписку, он отключится сам в день окончания.
- Трафик считается суммарно по всем серверам. Лимит в 100 ГБ общий, а не по 100 на каждый протокол.
- Пользователь `healthcheck` служебный, нужен для `vpn check`. В `vpn list` он не показывается, удалять его не нужно.

## 6. Лимит устройств и IP

Чтобы одну подписку не раздавали всем знакомым:

```
vpn add vasya 100 30 "оплатил" --devices 3 --ips 2   # сразу с лимитами
vpn limit vasya --devices 3 --ips 2                  # изменить у одного
vpn limit vasya                                      # посмотреть
vpn limit all --devices 3 --ips 2                    # у всех, кроме me
vpn limit default --devices 3 --ips 2                # для всех новых пользователей
vpn devices vasya                                    # какие устройства зарегистрированы
vpn devices vasya 2                                  # удалить устройство #2 (освободить место)
vpn devices vasya reset                              # сбросить все (человек сменил телефон)
vpn limit vasya --monthly                            # лимит ГБ — на месяц, трафик обнуляется ежемесячно
```

- **Трафик в месяц (`--monthly`).** Без него лимит ГБ — на весь срок: `vpn add vasya 1024 180` — это 1024 ГБ на полгода. С `--monthly` (в `vpn add` или `vpn limit`) 3x-ui обнуляет трафик пользователя каждый месяц в день создания или в день `--reset-day N`. Вернуть лимит на весь срок: `vpn limit vasya --no-monthly`. Дату следующего обнуления подписка отдаёт приложениям заголовком `Subscription-Refill-Date` (нужна короткая ссылка `https://домен/ID`; на старых установках включить один раз: `vpn refill`).

- **Устройства (`--devices`).** Happ, INCY и v2RayTun при обновлении подписки передают ID устройства. Первые N устройств регистрируются, следующему подписка не выдаётся. `vpn devices` показывает их по модели и клиенту.
  - Клиенты без ID устройства (sing-box: роутеры с Podkop или Tachyon, Hiddify) при лимите **не получат подписку вообще**. Таким пользователям ставьте `--devices 0` и ограничивайте только по IP.
  - При лимите устройств не откроется и личная страница подписки в браузере (кнопка «Сайт»).
- **IP (`--ips`).** Сколько разных IP одновременно могут пользоваться учёткой. Лишние адреса временно блокирует fail2ban: он ставится вместе с 3x-ui, а `vpn check` проверяет, что он работает.
  - Все устройства за одним домашним Wi-Fi считаются одним IP, а на мобильном интернете IP периодически меняется. Ставить меньше 2 не стоит.
- Вместе эти лимиты закрывают оба способа раздачи. На лишнем устройстве подписку не получить, а ссылки, скопированные из подписки вручную, не будут работать одновременно из многих мест.
- `0` означает без ограничения. `vpn limit all` не трогает пользователя `me`, чтобы не сломать ваш роутер.

## 7. Подпись подписки и названия серверов

То, что клиенты (INCY, Happ, v2RayTun, Hiddify) показывают на карточке подписки:

| Что | Где видно |
| --- | --- |
| Название | заголовок карточки подписки |
| Описание | текст под полоской трафика. `{{EMAIL}}` подставляет имя пользователя, `\n` переносит строку, до 200 символов |
| Поддержка | кнопка «Поддержка» (`@username` превращается в ссылку на Telegram) |
| Сайт | кнопка «Сайт»: ваша ссылка, `подписка` (личная страница пользователя с QR) или `-` (без кнопки) |
| Названия серверов | имена в списке серверов. По умолчанию флаг и страна: «🇳🇱 Нидерланды · VLESS» |
| Баннер | отдельная плашка со своим текстом и своей кнопкой (свой текст на кнопке и ссылка). Показывается в INCY и Happ, остальным клиентам не отправляется |

Остаток трафика («Осталось N дн.» и полоску) клиенты берут из стандартного заголовка подписки, настраивать его не нужно.

```
vpn brand                 # мастер: спросит всё по очереди, Enter оставляет как есть
vpn brand --show          # посмотреть текущие значения
vpn brand --auto-names    # названия по стране сервера

vpn brand --title "p0six KVN" --announce 'Привет, {{EMAIL}}\nОплата и вопросы: @admin' \
          --support @admin --site подписка

vpn brand --vless-name "🇫🇮 Финляндия · VLESS" --xhttp-name "🇫🇮 Финляндия · VLESS XHTTP" --hy2-name "🇫🇮 Финляндия · Hysteria2"
vpn brand --http3-name "🇫🇮 Финляндия · VLESS XHTTP HTTP3"     # если включён сервер HTTP3

vpn brand --support https://t.me/admin --site -          # «Поддержка» → Telegram, кнопку «Сайт» убрать
vpn brand --banner "Нужна помощь? Напишите нам" --banner-button "Написать" --banner-url @admin
vpn brand --banner -      # убрать баннер
```

Подписи стандартных кнопок «Поддержка» и «Сайт» рисует сам клиент на языке телефона, поменять их нельзя. `--support @username` превращается в ссылку `https://t.me/username`, можно сразу указать полную ссылку.

Если нужна кнопка со своим текстом, используйте **баннер** (`--banner`, `--banner-button`, `--banner-url`). Он показывается в INCY. В Happ он появится, только если в панели вручную включить управление Happ: оно заодно отправляет Happ свои настройки маршрутизации, поэтому `vpn` его не включает. Ссылка кнопки баннера одна на всех пользователей: личную страницу подписки (трафик, срок) открывает только стандартная кнопка «Сайт» (`--site подписка`). INCY и так показывает трафик и срок в карточке подписки.

Флаги можно указывать в любом наборе: остальные значения не меняются. После `vpn brand` панель перезапускается, VPN пропадает на пару секунд. Затем в клиентах нужно нажать «Обновить подписку».

## 8. Маскировка Reality

Reality выдаёт себя за TLS-соединение с настоящим сайтом (target/SNI). От выбора этого сайта сильно зависит, будет ли VLESS работать из России.

- **SNI крупных CDN (Cloudflare, Google, Amazon, Microsoft, Apple…) на чужом IP ТСПУ режет.** Так случилось при первой установке: автоподбор выбрал `www.cloudflare.com`, и VLESS не подключался из России, хотя Hysteria2 работал.
- **Лучше всего брать сайт из сети того же хостера.** Тогда SNI и IP «сходятся». Скрипт перебирает соседние IP (своя /24 и две соседние), берёт домены из их сертификатов, проверяет TLS 1.3, HTTP/2 и X25519 и выбирает самый быстрый. Домены CDN он пропускает.

```
vpn reality                              # текущая маскировка
vpn reality auto                         # подобрать в сети хостера и переключить
vpn reality <домен>                      # задать свою (проверяется перед применением)
vpn reality 213.165.59.85:443 site.ru    # target по IP + SNI (так делает auto)
```

- Смена применяется к обоим Reality-серверам (TCP и XHTTP). Ключи и пользователи сохраняются.
- **После смены клиентам нужно обновить подписку**, потому что SNI в ссылке меняется.
- Маскировку держит чужой сайт. Если он упадёт или сменит сертификат, `vpn check` покажет `[FAIL]` у маскировки. Тогда хватит снова запустить `vpn reality auto`.

### Свой домен: `vpn reality self` (рекомендуется)

Даже сайт из соседней сети не совпадает с IP сервера, и ТСПУ может периодически глушить такие подключения. На практике так выглядели «плавающие» n/a: `vpn trace` показывал, что после первого пакета рукопожатия с SNI соединение пропадает целиком. Коммерческие сервисы ставят в SNI **свой домен, указывающий на сам сервер**, а маскировкой служит свой сайт с настоящим сертификатом.

1. Купить дешёвый домен (.xyz, .space, .site — пара сотен рублей в первый год; не .ru/.рф). Имя нейтральное, без vpn/proxy.
2. Создать у регистратора A-запись, например `fi.домен.xyz` → IP сервера. AAAA не добавлять.
3. Через 5–15 минут:

```
vpn reality self fi.домен.xyz
```

Команда выпускает сертификат Let's Encrypt (через 80/tcp, с автопродлением) и поднимает nginx с сайтом-заглушкой только на localhost. Затем переключает VLESS TCP и XHTTP на этот домен. Клиентам остаётся обновить подписку. Подробнее — в [гайде по командам](docs/vpn-commands.md#vpn-reality-self--reality-на-свой-домен).

### Подписка на своём домене: `vpn sub-domain`

Если есть домен (A-запись → сервер), ссылка подписки станет короткой и без порта:

```bash
vpn sub-domain cdn.домен.tech     # https://cdn.домен.tech/<ID>
vpn link <имя>                    # новая ссылка и QR
```

Без порта ссылка получается, когда это тот же домен, что в `vpn reality self`: подписка отдаётся через 443 (Reality → nginx → панель). Для другого домена или с ключом `--port` адрес будет с портом. Вернуть IP: `vpn sub-domain off`.

Старые ссылки по IP перестают работать: сертификат выписан на домен. В клиентах добавь подписку заново по новой ссылке.

## 9. XHTTP и port hopping: когда оператор режет подключения

**Признаки:**
- на одной и той же сети то работает VLESS, а Hysteria2 нет, то наоборот;
- в клиенте сервера по очереди показывают n/a;
- приложения (например, Instagram) периодически подвисают.

Особенно часто так бывает на мобильном интернете: ТСПУ оператора по очереди душит разные протоколы. Конфигурацией одного сервера это не лечится. Помогает дать клиентам больше разных путей и включить в клиенте автовыбор сервера.

```
vpn xhttp on [порт]      # сервер VLESS XHTTP (по умолчанию 8443/tcp; при новой установке создаётся сам)
vpn xhttp off
vpn hop on [от-до]       # port hopping для Hysteria2 (по умолчанию UDP 20000-50000)
vpn hop off
```

- **XHTTP.** Изнутри похож на обычный HTTP/2-трафик браузера и лучше переносит замораживание TCP-соединений. Использует ту же маскировку Reality. Все пользователи, включая новых, добавляются автоматически. Клиенты на sing-box его не видят.
- **Port hopping.** Hysteria2 принимает подключения на целом диапазоне UDP-портов, клиент прыгает между ними. Это обходит блокировку по одному порту. На сервере это правило iptables в сервисе `vpn-hop`, которое заворачивает диапазон на 443. В ссылку добавляется параметр `mport`.
  - ⚠️ **Tachyon (и, вероятно, другие роутерные клиенты на sing-box) с hopping падает** с ошибкой `outbounds[N]: missing server_port`. Если у вас или у пользователей роутер на sing-box, держите hopping выключенным (`vpn hop off`).
- Если у хостера свой фаервол, откройте в нём порт XHTTP (8443/tcp) и, для hopping, UDP 20000–50000.
- После включения или выключения обновите подписку в клиентах. `vpn check` проверяет оба режима: порт, правило iptables, ссылку в подписке и сквозной тест XHTTP.

### Сервер HTTP3: `vpn http3` (когда глушат TCP)

Если `vpn trace` показывает, что TCP-подключения к серверу пропадают после первого пакета, а Hysteria2 (UDP) работает, добавь второй UDP-путь: сервер **HTTP3**. Это VLESS + XHTTP поверх HTTP/3 (QUIC) с настоящим TLS на твоём домене.

```
vpn reality self cdn.домен.tech                 # один раз: свой домен и сертификат
vpn http3 on 4443 --name "🇫🇮 Финляндия · VLESS XHTTP HTTP3"      # включить (порт и название можно не указывать)
vpn http3                                       # статус
vpn http3 off                                   # выключить
```

Сервер появится в подписке и в «⚡ Лучшем сервере». Работает в клиентах на ядре Xray (INCY, Happ, v2RayTun, v2rayN, Passwall на роутере). *Пометка:* в sing-box и в Tachyon (tachyon-core, на октябрь 2026) XHTTP поверх HTTP/3 нет, там HTTP3 будет n/a. Для них UDP-вариант — Hysteria2. Если у хостера свой фаервол, открой там UDP-порт. Подробнее — в [гайде](docs/vpn-commands.md#vpn-http3--сервер-http3-vless-xhttp-по-http3-quicudp).

### Фрагментация ClientHello: `vpn fragment`

Часть операторов режет TLS ClientHello на 443/TCP: VLESS по TCP перестаёт подключаться или работает рывками. Защита в несколько слоёв, большая часть уже есть по умолчанию:
- **Hysteria2** работает по UDP, эта блокировка её не касается.
- **VLESS XHTTP** на нестандартном порту (8443) — `vpn xhttp on`.
- **«⚡ Лучший сервер»** (`vpn fastest on`) сам уходит с заблокированного протокола на рабочий.
- **Фрагментация**: `vpn fragment on` — клиенты режут ClientHello на куски по 100–200 байт с паузой 10–20 мс, и DPI не видит его целиком. Включается на сервере для всех: маска `fragment` (xray finalmask) добавляется в JSON-подписку (Happ, v2RayTun, INCY — клиенты «Лучшего сервера»). Касается только TCP (VLESS, XHTTP). Параметры: `--packets tlshello|1-3`, `--length 100-200`, `--delay 10-20`; выключить — `vpn fragment off`, посмотреть — `vpn fragment status`. Клиентам — обновить подписку. Клиенты по обычным ссылкам (sing-box, роутеры) маску не получают.

### Доступ в домашнюю сеть без белого IP: `vpn reverse`

Роутер дома (OpenWrt / GL.iNet) сам держит исходящее подключение к основному серверу, а вы из любой сети заходите в домашнюю сеть через сервер. Белый IP, проброс портов и Tailscale не нужны. Под капотом встроенный обратный прокси VLESS (Xray 25.9+): роутер подключается как пользователь `rev-<имя>` с `reverse.tag`, и на сервере трафик выбранных пользователей к домашней подсети уходит в этот туннель.

```bash
vpn reverse add home --lan 192.168.8.0/24 --users me   # на основном сервере; печатает команду для роутера
vpn reverse list                                        # подключён ли роутер
vpn reverse router home                                 # команда для роутера ещё раз
vpn reverse del home                                    # удалить
```

На роутере (`ssh root@192.168.8.1`) выполните напечатанную команду: `router-bridge.sh` скачает Xray, положит конфиг в `/etc/xray-bridge` и запустит службу `xray-bridge` (procd, автозапуск). Удалить: `sh /tmp/rb.sh remove`.

- Заходить в домашнюю сеть можно только через серверы основного сервера (не через ноды и не через «Лучший сервер», если он выбрал ноду): именно к нему подключён роутер.
- Открывайте домашние адреса по IP (например `http://192.168.8.1`). Если приложение на телефоне пускает частные адреса мимо VPN (опция вроде «обход локальной сети»), выключите её.
- Роутер пропускает из туннеля только в подсеть `--lan`; выйти через ваш домашний интернет так нельзя.
- После `vpn promote` выполните `vpn reverse add` на новом основном заново и обновите команду на роутере.

## 9а. Сервер «Лучший сервер»

Как у коммерческих сервисов: первым в списке идёт **«⚡ Лучший сервер»**. Это балансировщик Xray (`leastPing` + `burstObservatory`): примерно раз в 10 секунд он пингует VLESS TCP, Hysteria2 и VLESS XHTTP через сам туннель и ведёт трафик через самый быстрый живой сервер. Если какой-то протокол зарежут, клиент сам переедет на другой, переключать вручную не нужно.

```
vpn fastest                                   # статус
vpn fastest on                                # включить (при новой установке включается сам)
vpn fastest on --name "🚀 Авто"               # своё название
vpn fastest on --clients happ,v2raytun,incy   # каким клиентам его отдавать (это значение по умолчанию)
vpn fastest on --interval 10s --sampling 2 --timeout 4s   # как быстро он замечает упавший сервер
vpn fastest off                               # выключить
```

- Обычные ссылки (`vless://`, `hysteria2://`) такой сервер описать не умеют, поэтому он отдаётся в **JSON-подписке Xray**. Тот же URL подписки сам определяет клиента по User-Agent: Happ, INCY и v2RayTun получают JSON с «Самым быстрым» и тремя обычными серверами, остальные — обычные ссылки, как раньше. Одна ссылка для всех.
- Список клиентов, получающих JSON, можно поменять: `vpn fastest on --clients happ,v2raytun,incy` (по умолчанию). Если какой-то клиент после этого показывает пустой список серверов, уберите его из списка.
- Роутеры на sing-box (Tachyon, Podkop) всегда получают обычные ссылки, у них свой автовыбор (url test).
- При включении и выключении XHTTP балансировщик обновляется сам.
- `vpn check` проверяет, что JSON-подписка отдаёт «Лучший сервер», и делает через него сквозной тест.
- **Скорость переключения.** Упавший сервер снимается с выбора через `interval × sampling` … `interval × sampling × 2` (по умолчанию 10s и 2: 20–40 секунд). Меньше значения — быстрее реакция, но больше ложных срабатываний на плохой сети; подробности в [гайде по командам](docs/vpn-commands.md).
- После `vpn fastest on/off` панель перезапускается (VPN моргнёт), затем обновите подписку в клиентах.

## 9б. Несколько серверов в одной подписке (ноды)

Второй (третий…) сервер подключается к текущему как **нода**. Пользователи, лимиты, трафик и подписка остаются на главном сервере. Серверы ноды просто появляются у всех в той же подписке и в «⚡ Лучшем сервере». Если IP одного сервера заблокируют, клиенты переедут на другой. Под капотом это режим нод самой 3x-ui (v3.9+): главная панель управляет 3x-ui на ноде через её API.

**1. На новом сервере** запусти установщик в режиме ноды. Он поставит 3x-ui и протоколы, всё проверит, но своих пользователей не создаст:

```bash
NODE=1 bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh)
```

Со своим поддоменом для маскировки и HTTP3 сразу (заранее создай A-запись `static` → IP ноды):

```bash
NODE=1 PROTOCOLS=vless,hy2,xhttp,http3 SELF_DOMAIN=static.твойдомен.tech \
bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh)
```

В конце он напечатает готовую команду для главного сервера, вида `vpn node add https://IP:порт/путь/ <токен> --name nl-…`. Она же сохраняется в `/etc/vpn/node-add.txt`. Если сервер уже поставлен обычным способом, сделай его нодой командой `vpn node prepare`. Она удалит его локальных пользователей и напечатает ту же команду.

**2. На главном сервере** выполни эту команду:

```bash
vpn node add https://IP_НОДЫ:ПОРТ/путь/ ТОКЕН --name nl-1
vpn node                 # список нод, их статус и серверы
vpn check --local        # в разделе «Ноды» — статус и сквозной тест каждого сервера ноды
```

**3.** Пользователи обновляют подписку, и в ней появляются серверы ноды.

Полезно знать:
- **Названия и маскировку настраивай на самой ноде** (заходи по ssh на ноду): `vpn brand --vless-name "🇩🇪 Германия · VLESS" --hy2-name "🇩🇪 Германия · Hysteria2" --xhttp-name "🇩🇪 Германия · VLESS XHTTP" --http3-name "🇩🇪 Германия · VLESS XHTTP HTTP3"`. Флаг страны установщик берёт из GeoIP; если у хостера один блок адресов на разные страны, флаг может оказаться не тем, тогда поправь так. Там же: `vpn reality self static.твойдомен.tech`, `vpn xhttp on`, `vpn http3 on`. Изменения сами доходят до главной панели. Если на ноде включил новый сервер, выполни на главном `vpn node sync`, чтобы на него добавились все пользователи.
- **Новые пользователи** (`vpn add` на главном) добавляются сразу на все серверы, включая ноды.
- **На ноде команды пользователей** (`vpn add`, `renew`, `limit`…) отключены, ими управляет главная панель.
- **Трафик по нодам:** `vpn traffic` на главном — сколько ГБ каждый пользователь прокачал через основной сервер и через каждую ноду (с последнего обнуления), `vpn traffic Anna` — один пользователь.
- **Закрыть ноду одному пользователю:** `vpn node block Anna fin-1` — у Anna серверы fin-1 пропадут из подписки, у остальных останутся; вернуть: `vpn node unblock Anna fin-1`. `vpn node sync` такое исключение не отменяет.
- **Временно убрать ноду из подписки:** `vpn node off fi-1`, вернуть: `vpn node on fi-1`. Пользователи и регистрация ноды остаются, переподключать ничего не надо. В клиентах — обновить подписку.
- **Переименовать ноду:** `vpn node rename de-xxxx swe-1`. Имя видно только в `vpn node` и командах; установщик берёт его из GeoIP и может ошибиться со страной. Подписку и пользователей это не трогает.
- **Отключить ноду:** `vpn node del nl-1`. Пользователи снимаются с её серверов, серверы уходят из подписки. Сама нода и её 3x-ui остаются. Чтобы подключить её снова, на ноде выполни `vpn node prepare`.
- **Порты у главного и у ноды могут совпадать**: например, HTTP3 на 4443/udp и там, и там. Каждый сервер слушает порт на своей машине.
- **У ноды должен быть открыт порт её панели** для главного сервера (`vpn panel hide` на ноде не работает).

### Смена основного сервера: `vpn promote`

Нода становится основной одной командой. Запускается **на ноде, которая станет основной**. Обратная смена — та же команда на другом сервере.

**Плановая смена** (оба сервера в сети):
```bash
vpn promote --from root@IP_ОСНОВНОГО
```
По ssh забирает со старого основного всех пользователей (UUID, ID подписок, лимиты, сроки, трафик), настройки подписки и подпись. Старый основной становится нодой нового, остальные ноды перепривязываются к новому основному (по ssh, на каждой выполняется `vpn node prepare`). «Лучший сервер» включается заново.

**Авария** (основной недоступен):
```bash
vpn promote --nodes root@IP_НОДЫ2,root@IP_НОДЫ3 --sub-link https://cdn.твойдомен/ID
```
Пользователи берутся из копии, которая есть на каждой ноде: UUID, ID подписок, лимит трафика, срок и лимит IP сохраняются. В копии нет счётчиков трафика (начнутся с нуля), лимитов устройств (станут «без лимита») и отключённых пользователей. `--sub-link` — любая старая ссылка подписки: из неё берутся домен, порт и путь, чтобы прежние ссылки заработали. `--nodes` — остальные ноды, их тоже перепривяжет к новому основному.

Что важно:
- **Пароли ssh.** Команда заходит на серверы по ssh под root. Пароль спрашивается один раз на сервер, удобнее заранее положить ключ: `ssh-copy-id root@IP`.
- **Перерыв.** На время переключения, пару минут, пользователи могут терять соединение. Копия пользователей сохраняется в `/root/vpn-promote-<дата>.json`: если что-то пойдёт не так, `vpn import <файл> --yes`.
- **DNS руками.** В конце команда напишет, какие A-записи поменять. Обычно домен подписки (`cdn`) переводится на новый основной, а поддомен нового основного (например, `media`) — на старый. После обновления DNS на новом основном: `vpn reality self cdn.твойдомен`, `vpn sub-domain cdn.твойдомен`, при HTTP3 `vpn http3 off && vpn http3 on`. На старом: `vpn reality self media.твойдомен`.
- **Панель.** Панель нового основного можно закрыть (`vpn panel hide`), у нод она должна оставаться открытой.
- **Адрес в ссылках.** Пока сервер был нодой, адрес в ссылки подставлял основной. `vpn promote` сам возвращает в ссылки IP нового основного. Если сервер сделали основным раньше этой версии скрипта и у Hysteria2 в ссылке домен подписки вместо IP (`vpn check` пишет «В ссылках этого сервера не его адрес»), выполните `vpn repair`.
 Токен ноды даёт полный доступ к её панели, не публикуй его.

| `vpn brand [...]` | подпись подписки, кнопки «Поддержка» и «Сайт», названия серверов, баннер со своей кнопкой (`--banner`) |
| `vpn reality [auto\|<домен>\|<ip:443> <домен>]` | маскировка Reality |
| `vpn sub-domain <домен> [--port] \| off \| status` | ссылка подписки `https://домен/<ID>` вместо IP с портом |
| `vpn reality self <свой домен>` | Reality на свой домен: сертификат, сайт-заглушка, SNI = домен |
| `vpn xhttp on [порт] \| off` | сервер VLESS XHTTP |
| `vpn http3 on [порт] [--name Т] \| off` | сервер HTTP3: VLESS XHTTP по HTTP/3 (QUIC, UDP) на своём домене |
| `vpn hop on [от-до] \| off` | port hopping для Hysteria2 |
| `vpn fastest [on\|off\|status] [--name Т] [--clients …] [--interval --sampling --timeout]` | сервер «⚡ Лучший сервер» |
| `vpn check [--local]` | полная диагностика (`--local` — без проверки снаружи) |
| `vpn repair` | вернуть в ссылки адрес этого сервера (после `vpn promote`) |
| `vpn fragment on\|off\|status` | фрагментация TLS ClientHello у клиентов (от блокировок 443/TCP) |
| `vpn reverse add <имя> [--lan CIDR] [--users me] \| list \| router <имя> \| del <имя>` | доступ в домашнюю сеть без белого IP: роутер сам подключается к серверу |
| `vpn traffic [имя]` | трафик пользователей по серверам: основной и каждая нода |
| `vpn refill` | дата обнуления трафика в подписке (заголовок `Subscription-Refill-Date`) |
| `vpn node` / `vpn node add <адрес> <токен> [--name имя]` | ноды: список / подключить сервер-ноду к этой подписке |
| `vpn node sync` / `vpn node del <имя>` | дотянуть новые серверы нод и всех пользователей / отключить ноду |
| `vpn node off\|on <имя>` | временно убрать серверы ноды из подписки / вернуть |
| `vpn node block\|unblock <пользователь> <нода>` | убрать ноду из подписки одного пользователя / вернуть |
| `vpn node rename <имя> <новое>` | переименовать ноду (только служебное имя, подписка не меняется) |
| `vpn promote [--from root@IP] [--nodes root@IP,…] [--sub-link ссылка]` | (на ноде) сделать её основным сервером: плановая смена или авария |
| `vpn node prepare` | (на новом сервере) сделать его нодой и показать команду для главного |
| `vpn export [файл]` / `vpn import <файл\|x-ui.db>\|--from root@IP\|--links <файл> [--update]` | перенос пользователей на другой сервер: со старого выгрузить / на новом принять, ссылки подписок сохраняются |
| `vpn trace [IP] [секунд]` | запись подключений клиента и разбор: дошли ли до сервера, ответил ли он, не теряются ли ответы |
| `vpn panel [hide\|show\|status]` | адрес, логин и пароль панели; `hide` закрывает её снаружи (доступ через ssh-туннель) |
| `vpn help` | справка |

## 11. Панель 3x-ui

Адрес, логин и пароль показывает `vpn panel` (в любое время, даже когда панель закрыта снаружи). **Секретный путь** — случайная часть адреса, которую установщик генерирует при установке (`https://IP:ПОРТ/aB3xK9qLm2/`). Без неё панель отвечает 404 и не показывает даже страницу входа. Это дополнительная защита поверх логина и пароля. Если сменить путь в настройках панели, `vpn panel` покажет старый адрес, а актуальный покажет `x-ui settings`. Снаружи панель не нужна: `vpn panel hide` закроет её (слушает только 127.0.0.1, порт закрыт в ufw), открывать можно через ssh-туннель, вернуть доступ можно командой `vpn panel show`.

- **Где смотреть:** Dashboard (нагрузка, трафик, версия Xray), Inbounds (три сервера), Clients (пользователи, кто онлайн, их IP).
- **Что можно менять в панели:** Telegram-бота, лимиты и сроки пользователей. Всё, что сделано в панели, видит `vpn`, и наоборот.
- **Что лучше делать через `vpn`:** маскировку, названия, подпись, XHTTP и hopping. Утилита держит согласованными несколько мест сразу.
- **Чего не трогать:** порты и протоколы inbound'ов, сертификаты в Hysteria2.
- **Не перевыпускайте API-токен `vpn-cli`.** На нём работает утилита `vpn`, как починить — в [разделе 12](#12-диагностика-и-типичные-проблемы).

## 12. Диагностика и типичные проблемы

**Первым делом запустите `vpn check`.** Команда проверит всё и для каждой ошибки (`[FAIL]`) подскажет, что делать.

| Симптом | Причина и что делать |
| --- | --- |
| Скрипт: «Заняты порты» | Скрипт показывает, какие процессы заняли порты. Остановите их и запустите скрипт заново |
| Скрипт: «443/tcp закрыт снаружи» | Откройте 443/tcp и 443/udp в фаерволе хостера |
| «из России НЕТ», а из Европы да | IP заблокирован в РФ, нужен VPS с другим IP |
| `Сертификат: selfsigned` | Let's Encrypt не достучался до 80/tcp. Откройте порт у хостера и переустановите, пока нет пользователей |
| Не работает ничего | `systemctl status x-ui`, `ss -ltnup \| grep 443`, `ufw status`, фаервол у хостера |
| Hysteria2 работает, VLESS нет | ТСПУ режет SNI маскировки: `vpn reality auto` и обновить подписку ([раздел 8](#8-маскировка-reality)) |
| Не работает только Hysteria2 | Сеть режет UDP или у хостера закрыт 443/udp. Пользуйтесь VLESS |
| Через домашний роутер не работает, с мобильного работает | DPI-обход на роутере (zapret/nfqws) портит трафик до VPS. Исключите IP сервера из его обработки |
| Серверы «плавают» в n/a и на Wi-Fi, и на мобильном; `vpn trace` показывает «СЕРВЕР МОЛЧИТ» | ТСПУ глушит подключения после рукопожатия с чужим SNI. Решение — свой домен: `vpn reality self <домен>` ([раздел 8](#свой-домен-vpn-reality-self-рекомендуется)) |
| Протоколы по очереди показывают n/a, приложения подвисают | Оператор душит протоколы ([раздел 9](#9-xhttp-и-port-hopping-когда-оператор-режет-подключения)). Чтобы убедиться, что дело не в сервере, запустите мониторинг (ниже) |
| Tachyon/sing-box не стартует: `missing server_port` | Включён port hopping: `vpn hop off`, затем обновите подписку на роутере |
| В INCY/Happ не видно сервера XHTTP на роутере | Норма: sing-box не поддерживает XHTTP |
| Новое устройство не получает подписку | Достигнут лимит устройств: `vpn devices <имя>`, удалить старое или `reset` |
| `vpn`: «токен недействителен» | Починка токена (ниже) |
| Пользователь пишет, что VPN пропал | `vpn list`: кончился трафик или срок. Тогда `vpn renew` |
| Пропал SSH после установки | Зайдите через VNC-консоль хостера и выполните `ufw allow <порт>/tcp` |

**Мониторинг: сервер сбоит или путь до него?** Минут десять сервер проверяет сам себя каждые 15 секунд. Одновременно жмите тест задержки в клиенте и запоминайте время, когда видите n/a:

```bash
journalctl -u x-ui --since "-3h" --no-pager | grep -c "Xray .* started"     # сколько раз перезапускался Xray
for i in $(seq 40); do printf '%s  ' "$(date +%T)"; vpn check --local 2>&1 | sed 's/\x1b\[[0-9;]*m//g' | grep -E 'работает,|не смог' | awk '{printf "%s %s  ", $1, $2}'; echo; sleep 15; done
```

- **На сервере в те же моменты `[FAIL]`:** проблема на сервере, смотрите `journalctl -u x-ui --since "-15min"`.
- **На сервере всё время `[OK]`, а в клиенте n/a:** проблема на пути до сервера. Помогут XHTTP и hopping, смена хостера или, с доменом, XHTTP через CDN.

**Что именно происходит с подключениями клиента:** `vpn trace <IP клиента>` (2 минуты, Ctrl+C — раньше). Пока идёт запись, жмите тест в клиенте. В конце по каждому подключению будет итог: не дошло, сервер не ответил, ответы теряются по пути назад или всё `ok`. Как читать — в [гайде по командам](docs/vpn-commands.md#vpn-trace--что-происходит-с-подключениями-клиента).

**Проверка ресурсов сервера**, если есть подозрение на него:

```bash
for f in 4 6; do curl -$f -s -o /dev/null --max-time 20 -w "%{speed_download}\n" "https://speed.cloudflare.com/__down?bytes=50000000" | awk -v f=$f '{printf "IPv%s: %.0f Мбит/с\n", f, $1*8/1e6}'; done
vmstat 1 5        # колонка st — процессор, отнятый хостером (должна быть около 0)
```

**Какие сообщения в логе — не проблема:**
- `http: TLS handshake error … EOF` — узлы check-host.net во время `vpn check` и сканеры портов;
- `Server shutdown failed … use of closed network connection` — штатный перезапуск панели (`vpn brand` и т. п.).

**Починка токена `vpn`:**

```bash
T=$(/usr/local/x-ui/x-ui setting -getApiToken -tokenName vpn-cli | grep -Eo 'apiToken: .+' | awk '{print $2}')
sed -i "s|^TOKEN=.*|TOKEN='$T'|" /etc/vpn/vpn.env && vpn list
```

**Переустановка с нуля** (удаляет всех пользователей). Запустите скрипт ещё раз: он увидит существующий 3x-ui, предложит переустановку и перед удалением сохранит бэкап в `/root/x-ui-before-reinstall-*.tgz`. Let's Encrypt выдаёт не больше 5 одинаковых сертификатов в неделю, так что часто переустанавливать не стоит.

## 13. Частые вопросы

**Будут ли проблемы, если клиенты одновременно сидят на разных протоколах?** Нет. Серверы независимы. Один пользователь может даже одновременно сидеть с телефона через Hysteria2 и с ноутбука через VLESS: трафик сложится в общий лимит. Учтите только лимит IP (`--ips`): адреса считаются со всех протоколов вместе.

**Сколько пользователей выдержит 1 vCPU / 2 ГБ?** Десятки. VLESS Vision почти не нагружает процессор, Hysteria2 и XHTTP нагружают больше, но на современном CPU это всё равно сотни Мбит/с. Чаще упираешься в канал хостера, а он общий для всех.

**Почему в клиенте два одинаковых имени сервера?** Если задать одинаковые названия, клиенты различают серверы по протоколу (VLESS · TCP · REALITY, Hysteria2 · UDP · TLS). Чтобы было нагляднее, задайте разные имена через `vpn brand`.

**Почему при изменениях пропадает VPN на пару секунд?** `vpn brand`, `vpn reality`, `vpn xhttp` и `vpn limit` меняют конфиг, и Xray перезапускается, разрывая текущие соединения. Клиенты переподключаются сами.

**Что видит пользователь, когда кончился трафик или срок?** Подключения перестают работать, а в клиенте видно, что трафик исчерпан или дата прошла. После `vpn renew` или `vpn reset` всё работает по той же ссылке.

- **Обновить утилиту `vpn`** до версии из репозитория. Сервер и пользователи не затрагиваются:

- **Бэкап** раз в неделю, затем скачайте архив к себе. Либо включите Telegram-бота, он присылает базу сам:
  ```bash
  tar czf /root/vpn-backup-$(date +%F).tgz /etc/x-ui /etc/vpn /root/cert /root/.acme.sh /usr/local/bin/vpn /etc/systemd/system/vpn-hop.service 2>/dev/null
  ```
- **Обновления системы** раз в месяц: `apt update && apt upgrade -y`, после обновления ядра — `reboot`. Всё поднимется само.
- **`x-ui update` без необходимости не запускайте.** В новой версии 3x-ui может измениться API, на котором работает `vpn`. Ядро Xray безопаснее обновлять из Dashboard панели.
- **Сертификат** продлевается сам, если открыт порт 80. Проверить: `~/.acme.sh/acme.sh --list`. В `vpn check` порт 80 может показываться «доступным» без сервиса: между продлениями на нём никто не слушает, и это нормально.

## 14а. Переезд на новый сервер

Пользователи, ключи, ссылки подписок, сроки, лимиты и израсходованный трафик переносятся командами `vpn export` и `vpn import`. Если подписка выдана на домене (`vpn sub-domain`), клиентам ничего делать не нужно: после переключения DNS прежние ссылки работают уже с нового сервера. Старый сервер можно держать до конца аренды как запасной.

**1. Заранее.** За день понизьте TTL A-записи домена подписки до 300 секунд (у регистратора). На старом сервере обновите `vpn`, пользователи при этом не затрагиваются:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh) --cli
```

**2. Новый сервер.** Поставьте на него скрипт как обычно, с теми же протоколами. `SELF_DOMAIN` пока не задавайте: домен ещё указывает на старый сервер, а новый можно проверить по IP.

**3. Перенос.** На **новом** сервере (спросит пароль root старого):

```bash
vpn import --from root@IP_СТАРОГО_СЕРВЕРА
```

Если на старый сервер нельзя зайти по ssh с нового, сделайте через файл: на старом `vpn export /root/vpn-clients.json`, скопируйте файл (`scp`), на новом `vpn import /root/vpn-clients.json`, потом удалите файл на обоих (в нём ключи пользователей).

Команда спросит подтверждение и перенесёт всех. В конце она напечатает, что делать дальше, с вашими доменами.

**4. Проверка по IP.** `vpn link me` на новом сервере даёт ссылку с тем же ID, что был на старом. Добавьте её в клиент и проверьте работу всех серверов подписки.

**5. Переключение.** Когда всё проверено:

1. Перед переключением повторите `vpn import --from root@IP_СТАРОГО --update`: подтянутся новые пользователи, продления и израсходованный трафик, появившиеся на старом сервере после первого переноса.
2. Переведите A-запись домена на IP нового сервера и подождите TTL (5–15 минут).
3. На новом сервере выполните команды, которые напечатал `vpn import`, обычно:
   ```bash
   vpn reality self ваш.домен
   vpn sub-domain ваш.домен
   vpn http3 on          # если на старом был включён
   ```
4. Клиенты подхватят новый сервер при следующем обновлении подписки (раз в 6 часов или по кнопке «Обновить»). До этого они ходят на старый сервер, поэтому не выключайте его сразу.

**Что переносится:** имя, UUID, ключ Hysteria2, ID подписки, лимиты трафика, устройств и IP, срок, включён или отключён, комментарий, израсходованный трафик, порт и путь подписки (чтобы старые ссылки заработали), подпись подписки (название, описание, поддержка, сайт) и лимиты по умолчанию (`vpn limit default`).

**Что не переносится, настраивается заново:**
- ключи Reality и сертификаты: на новом сервере свои, клиенты получают их из подписки;
- названия серверов: в них флаг страны (при желании `vpn brand`);
- протоколы и порты: выбираются при установке, а `vpn http3 on`, `vpn xhttp on`, `vpn hop on` и `vpn fastest on` при необходимости включите после переноса, `vpn import` напомнит, что было включено на старом;
- устройства (HWID): регистрируются заново при первом обновлении подписки;
- ноды, Telegram-бот, пароль панели.

**Если старый сервер не загружается.** Данные можно достать из файла базы 3x-ui `x-ui.db`, и `vpn import` читает его так же, как обычную выгрузку:

```bash
vpn import /root/x-ui.db --yes
```

Откуда взять файл:
- **снапшот или автобэкап** в панели хостера: восстановите его в отдельный сервер и скопируйте `/etc/x-ui/x-ui.db`;
- **rescue-режим** хостера: смонтируйте диск и скопируйте `/etc/x-ui/x-ui.db` **вместе с `x-ui.db-wal` и `x-ui.db-shm`**, если они рядом (в них самые свежие записи), в одну папку;
- **Telegram-бот** 3x-ui, если он был включён: поищите в чате с ботом присланный файл `x-ui.db`.

База даёт всё: пользователей, трафик, порт и путь подписки, подпись.

Если базы нет совсем, пользователей можно восстановить по сохранённым **ссылкам подписок** (в переписке с клиентами). Создайте файл, по строке на пользователя: имя, ссылка, при желании ГБ и дни (без них: без лимитов).

```
vasya  https://cdn.example.com:42784/путь/dnnsbqwwdbz  50  30
petya  https://cdn.example.com:42784/путь/abc12345xyz
```

и выполните `vpn import --links /root/links.txt --yes`. Пользователи создаются с теми же ID подписок, порт и путь берутся из ссылок, поэтому ссылки продолжают работать. Ключи (UUID) у них новые, клиенты получат их при обновлении подписки. Срок и лимиты, которых не знаете, поправьте потом: `vpn expire`, `vpn limit`, `vpn renew`. Один пользователь: `vpn add <имя> <ГБ> <дней> --sub-id <ID из старой ссылки>`. У тех, чьей ссылки не осталось, ссылка будет новая.

Параметры `vpn import`: `--update` (перезаписать уже существующих пользователей данными со старого сервера, включая срок, лимиты и трафик; без него они пропускаются, а новые создаются), `--no-links` (не менять порт и путь подписки), `--no-brand` (не копировать подпись подписки), `--yes` (без вопроса).

Если подписка выдавалась **по IP** старого сервера, без домена, привязанные к IP ссылки перенести нельзя: пользователям придётся добавить новую (`vpn link <имя>`). Чтобы следующий переезд был незаметным, заведите домен: `vpn reality self <домен>`, затем `vpn sub-domain <домен>`.

## 15. Безопасность

- После того как вход по ключу проверен, отключите вход по паролю: `PasswordAuthentication no` в `/etc/ssh/sshd_config`, затем `systemctl restart ssh`.
- Ссылка на панель, пароль и файлы в `/etc/vpn/` — только для вас. Пользователям отдаётся только ссылка-подписка.
- Ссылка-подписка даёт доступ к VPN. Если она утекла, выполните `vpn del` и `vpn add`: пользователь получит новую. Против раздачи подписки — [лимиты устройств и IP](#6-лимит-устройств-и-ip).
- Если IP сервера заблокируют, поднимите новый VPS этим же скриптом и перенесите пользователей командой `vpn import` ([14а](#14а-переезд-на-новый-сервер)). Если подписка на домене, достаточно переключить A-запись, ссылки останутся прежними.
- Если вы берёте за доступ деньги, учитывайте требования законодательства вашей страны к VPN-сервисам (в РФ, например, запрещена реклама VPN и есть отдельные требования к провайдерам VPN).
