# Утилита `vpn`: подробный гайд

`vpn` — консольная утилита на сервере, через которую управляется весь VPN-сервис: пользователи, лимиты, подпись подписки, маскировка, дополнительные протоколы и диагностика. Она обращается к панели 3x-ui через её API, поэтому всё, что сделано через `vpn`, видно в панели, и наоборот.

- Запускается **на сервере от root**: `vpn <команда> …`.
- Справка: `vpn help`.
- Устанавливается вместе со скриптом; как обновить — в [разделе 7](#7-обслуживание-самой-утилиты).

## 1. База: пользователи

Пользователь — это одна учётка с одной ссылкой-подпиской. В подписке все серверы сразу (VLESS TCP, Hysteria2, VLESS XHTTP; при установке можно было выбрать не все), трафик по ним считается общим.

**Правила для всех команд:**
- **Имя пользователя:** латиница, цифры и `. _ - @`, до 64 символов (`vasya`, `petrov.ivan`, `tg@12345`). Имя — это и идентификатор, и подпись в панели. Переименовать нельзя, только удалить и создать заново.
- **Гигабайты** можно дробно (`0.5`), **дни** — целым числом.
- **`0`** означает «без лимита» для трафика и «бессрочно» для срока.

### `vpn add` — создать пользователя

```
vpn add <имя> <ГБ> <дней> [комментарий] [--devices N] [--ips N]
```

```
vpn add vasya 100 30                          # 100 ГБ на 30 дней
vpn add vasya 100 30 "оплатил 11.10, 300р"    # с комментарием (виден в vpn list)
vpn add mama 0 0 "семья"                      # без лимита трафика и бессрочно
vpn add test1 5 3 "пробный"                   # пробный доступ: 5 ГБ на 3 дня
vpn add vasya 100 30 --devices 3 --ips 2      # сразу с лимитом устройств и IP (раздел 3)
```

Что происходит:
- Создаётся пользователь со случайной ссылкой-подпиской. Он добавляется сразу на все серверы, включая XHTTP, если он включён.
- Срок отсчитывается от текущего момента: `30` дней — это ровно 30×24 часа.
- Если лимиты устройств и IP не указаны, берутся значения по умолчанию из `vpn limit default` (изначально без лимита).
- В конце выводится ссылка подписки и QR-код: её и отправляете пользователю.

### `vpn link` — ссылка подписки

```
vpn link vasya
```

Выводит ссылку и QR-код ещё раз. Ссылка постоянная: она не меняется при продлении, сбросе трафика или включении и выключении. Меняется только при `del` + `add`.

### `vpn list` — все пользователи

```
vpn list
```

```
ИМЯ    ВКЛ  ИСПОЛЬЗ.  ЛИМИТ   ДО                УСТР./IP  КОММЕНТАРИЙ
me     да   12.4 ГБ   ∞       бессрочно         ∞/∞       владелец
vasya  да   37.1 ГБ   100 ГБ  10.11.2026_14:00  3/2       оплатил 11.10
petya  нет  10 ГБ     10 ГБ   18.10.2026_13:22  ∞/∞       -
```

| Колонка | Что значит |
| --- | --- |
| ВКЛ | `нет`: пользователь отключён вручную (`vpn off`), кончился трафик или вышел срок |
| ИСПОЛЬЗ. | сколько потрачено (скачано + отдано, по всем протоколам) |
| ЛИМИТ | лимит трафика, `∞` — без лимита |
| ДО | дата и время окончания; `бессрочно`; `с_1-го_подкл.` — срок начнётся с первого подключения (ставится в панели) |
| УСТР./IP | лимит устройств / лимит одновременных IP, `∞` — без лимита |

Служебный пользователь `healthcheck` (нужен для `vpn check`) в списке не показывается.

### `vpn renew` — продлить

```
vpn renew <имя> <дней> [ГБ]
```

```
vpn renew vasya 30          # +30 дней, трафик обнулить
vpn renew vasya 30 200      # +30 дней, новый лимит 200 ГБ, трафик обнулить
vpn renew vasya 0 150       # срок не менять, лимит 150 ГБ, трафик обнулить (докупил трафик)
```

- **Дни прибавляются к текущей дате окончания**, если она ещё не наступила: заплатил заранее, ничего не потерял. Если срок уже истёк, дни считаются от сегодняшнего дня.
- **`0` дней — срок не меняется.** Если срок уже истёк, утилита предупредит, что пользователь не подключится, пока не продлишь на дни.
- У бессрочного пользователя `renew <имя> 30` ставит срок 30 дней от сегодня.
- Счётчик трафика всегда обнуляется, пользователь включается. Подключение по старой ссылке сразу работает.

### `vpn expire` — задать срок без сброса трафика

```bash
vpn expire anna 30    # действует 30 дней от сегодняшнего дня
vpn expire anna 0     # бессрочно
```

Меняет только срок: трафик не обнуляется (в отличие от `vpn renew`). Дата окончания приходит клиентам в заголовке подписки, поэтому INCY, Happ, v2RayTun и Tachyon показывают её рядом с остатком трафика после обновления подписки. У бессрочного пользователя (срок 0) даты нет, показывать нечего.

### `vpn reset` — обнулить трафик

```
vpn reset vasya
```

Только обнуляет счётчик трафика (и включает пользователя, если он был отключён из-за исчерпанного лимита). Срок и лимит не меняются. Пример: месяц тот же, но человек всё выбрал, и вы решили дать ещё столько же.

### `vpn off` / `vpn on` — отключить и включить

```
vpn off vasya
vpn on vasya
```

Временно блокирует доступ, ничего не удаляя: трафик, срок, ссылка и устройства сохраняются. Удобно, если человек просрочил оплату на пару дней.

### `vpn del` — удалить

```
vpn del vasya
```

Удаляет пользователя со всех серверов вместе со статистикой. Его ссылка перестаёт работать навсегда. Отмены нет.

### `vpn panel` — доступ к панели

```
vpn panel
```

Показывает адрес веб-панели 3x-ui, логин и пароль. Команда работает в любое время, в том числе когда панель закрыта снаружи. Данные хранятся в `/etc/vpn/panel.txt`, прочитать его может только root.

**Секретный путь** — случайная часть адреса, которую установщик генерирует при установке: в `https://IP:ПОРТ/aB3xK9qLm2/` это `aB3xK9qLm2`. Без него панель отвечает 404 и даже страницу входа не показывает, поэтому сканер портов не поймёт, что здесь 3x-ui. Это дополнительная защита поверх логина и пароля, а не замена им. Путь можно сменить в настройках панели; тогда `vpn panel` покажет старый адрес, а актуальный путь покажет `x-ui settings`.

#### Закрыть панель снаружи: `vpn panel hide`

```
vpn panel hide      # панель слушает только 127.0.0.1, порт закрыт в ufw
vpn panel show      # открыть как было
vpn panel status
```

По умолчанию панель доступна из интернета на случайном порту (защищена секретным путём, логином и паролем). Для работы утилиты `vpn`, подписок и VPN она снаружи не нужна: `vpn` ходит в неё по 127.0.0.1. После `hide` панель открывается только через ssh-туннель:

```bash
ssh -N -L ПОРТ:127.0.0.1:ПОРТ root@IP_СЕРВЕРА     # порт и адрес покажет vpn panel
# в браузере: https://127.0.0.1:ПОРТ/секретный-путь/
```

Команда перезапускает панель (VPN моргнёт на пару секунд). Если у хостера есть свой фаервол, порт панели там можно закрыть тоже. `vpn check` не проверяет закрытую панель снаружи. На ноде `hide` недоступен: главный сервер ходит в её панель по сети.

## 2. Типовые сценарии

| Ситуация | Команда |
| --- | --- |
| Новый клиент оплатил месяц, 100 ГБ | `vpn add vasya 100 30 "оплатил 11.10"`, отправить ему ссылку |
| Оплатил следующий месяц | `vpn renew vasya 30` |
| Кончился трафик раньше срока, докупил 150 ГБ | `vpn renew vasya 0 150` |
| Даёте ещё столько же трафика бесплатно | `vpn reset vasya` |
| Пробный доступ | `vpn add test1 5 3 "пробный"` |
| Не заплатил | ничего: в дату окончания отключится сам. Или сразу `vpn off vasya` |
| Заплатил после отключения | `vpn renew vasya 30` (дни считаются от сегодня) |
| Сменил телефон и не может получить подписку | `vpn devices vasya reset` |
| Ссылка утекла | `vpn del vasya` и `vpn add vasya …`: ссылка будет новая, старая умрёт |
| Пишет «VPN не работает» | `vpn list` (не кончились ли трафик и срок), затем `vpn check` |
| Кто сколько тратит | `vpn list` |

## 3. Лимиты устройств и IP

Нужны, чтобы одну подписку не раздавали бесконечно. Лимитов два, работают они по-разному, и лучше ставить оба.

| Лимит | Что ограничивает | Как работает |
| --- | --- | --- |
| `--devices N` | сколько устройств могут **получать подписку** | Клиенты Happ, INCY и v2RayTun при обновлении подписки передают ID устройства. Первые N запоминаются, следующему подписка не выдаётся |
| `--ips N` | сколько IP **одновременно** пользуются учёткой | Лишние адреса временно блокирует fail2ban. Работает и против ссылок, скопированных из подписки вручную |

`0` везде означает без ограничения.

### `vpn limit` — задать лимиты

```
vpn limit <имя|all|default> [--devices N] [--ips N]
```

```
vpn limit vasya                         # посмотреть лимиты пользователя
vpn limit vasya --devices 3 --ips 2     # задать оба
vpn limit vasya --devices 0             # снять лимит устройств (IP-лимит не трогается)
vpn limit all --devices 3 --ips 2       # всем существующим, кроме me
vpn limit default --devices 3 --ips 2   # для всех НОВЫХ пользователей (vpn add)
vpn limit default                       # посмотреть значения по умолчанию
```

- Указывайте только то, что меняете: второй лимит останется как был.
- `all` не трогает пользователя `me`, чтобы не сломать ваш роутер (см. ниже).
- `default` влияет только на будущие `vpn add`, существующих не меняет.

### `vpn devices` — устройства пользователя

```
vpn devices <имя> [reset|<номер>]
```

```
vpn devices vasya          # список
vpn devices vasya 2        # удалить устройство #2 (освободить место)
vpn devices vasya reset    # удалить все (человек сменил телефон)
```

```
vasya: устройств 2 из 3
  #2  iPad ios 18  Happ/3.1  последний раз: 11.10 13:22
  #1  Pixel 9 android 15  INCY/3.7.0  последний раз: 11.10 13:20
```

Устройства видны и без лимита: так можно посмотреть, сколько их у человека на самом деле, прежде чем ставить ограничение.

### Важные нюансы

- **Роутеры и sing-box не передают ID устройства.** Podkop, Tachyon и другие клиенты на sing-box при включённом лимите устройств **не получат подписку вообще**. Таким пользователям ставьте `--devices 0` и ограничивайте только по `--ips`.
- **При лимите устройств не открывается личная страница подписки в браузере** (кнопка «Сайт»): браузер ID устройства не передаёт.
- **IP — это не устройства.** Вся семья за одним домашним Wi-Fi считается одним IP, а на мобильном интернете IP периодически меняется. Меньше `--ips 2` ставить не стоит.
- **Для лимита IP нужен fail2ban.** Он ставится вместе с 3x-ui. `vpn limit`, `vpn add` и `vpn check` предупредят, если он не запущен. Включить: `x-ui` → IP Limit Management → Install.

## 4. Как выглядит подписка

### `vpn brand` — подпись и названия серверов

Клиенты (INCY, Happ, v2RayTun, Hiddify) показывают на карточке подписки название, описание и кнопки, а в списке — названия серверов. Всё это задаётся одной командой.

| Параметр | Флаг | Где видно |
| --- | --- | --- |
| Название | `--title` | заголовок карточки подписки |
| Описание | `--announce` | текст под полоской трафика. `{{EMAIL}}` подставит имя пользователя, `\n` перенесёт строку, до 200 символов |
| Поддержка | `--support` | кнопка «Поддержка»: `@username` (станет ссылкой на Telegram), любая ссылка или `-` (без кнопки) |
| Сайт | `--site` | кнопка «Сайт»: ссылка, `подписка` (личная страница пользователя с QR) или `-` (без кнопки) |
| Названия серверов | `--vless-name`, `--hy2-name`, `--xhttp-name`, `--http3-name` | имена серверов в списке клиента (`--http3-name` — если включён `vpn http3`) |
| Названия по стране | `--auto-names` | «🇫🇮 Финляндия · VLESS» и т. п., страна определяется по IP сервера |

```
vpn brand                 # мастер: спросит всё по очереди, Enter оставляет как есть
vpn brand --show          # текущие значения

vpn brand --title "p0six KVN"
vpn brand --announce 'Привет, {{EMAIL}}!\nОплата и вопросы: @p0six' --support @p0six --site подписка
vpn brand --vless-name "FIN - VLESS TCP" --xhttp-name "FIN - VLESS XHTTP" --hy2-name "FIN - Hysteria2"
vpn brand --auto-names
```

- Флаги можно указывать в любом наборе: остальное не меняется.
- Описание берите в **одинарные кавычки**, иначе `\n` и `!` может испортить shell.
- Остаток трафика и дней («Осталось N дн.», полоска) клиенты рисуют сами из стандартного заголовка, отдельно их настраивать не нужно.
- **После сохранения панель перезапускается**, VPN пропадает на 2–3 секунды. Затем в клиентах нужно нажать «Обновить подписку».

### `vpn sub-domain` — ссылка подписки на своём домене

```bash
vpn sub-domain cdn.example.tech           # https://cdn.example.tech/<ID>, без порта и пути
vpn sub-domain cdn.example.tech --port    # с портом: https://cdn.example.tech:порт/путь/<ID>
vpn sub-domain status                     # что сейчас
vpn sub-domain off                        # вернуть адрес по IP
```

По умолчанию подписка живёт на IP сервера с портом и длинным путём. С доменом ссылка короче и не меняется при переезде на другой IP.

**Короткая ссылка без порта.** Если домен тот же, что в `vpn reality self` (Reality на 443), подписка отдаётся через 443: Reality передаёт всё, что не является VPN-клиентом, на сайт-заглушку (nginx), а nginx по адресу `/<ID>` отдаёт подписку из панели. Ссылка получается вида `https://cdn.example.tech/iwwh2osbrgshensh`. Заглушка и остальные адреса отвечают как раньше. Для любого другого домена (или с ключом `--port`) ссылка остаётся с портом, потому что 443/tcp занят Reality.

Команда:
1. проверяет, что A-запись домена указывает на этот сервер;
2. берёт сертификат Reality-домена, а для другого домена выпускает Let's Encrypt сама (нужен свободный 80/tcp, сертификат в `/etc/vpn/sub/`);
3. прописывает адрес и сертификат в настройках подписок, при короткой ссылке добавляет проксирование в nginx, перезапускает панель (VPN моргнёт на пару секунд) и проверяет, что подписка реально отдаётся по новому адресу. Если нет, прежние настройки возвращаются сами.

**Что делать после включения:** ID подписки у каждого пользователя тот же, адрес другой. `vpn link <имя>` покажет новую ссылку и QR, в клиентах подписку нужно добавить заново, а старую удалить. Серверы внутри подписки не меняются: они по-прежнему указывают на IP. Старая ссылка с портом при этом тоже продолжает отвечать, но по IP клиент откажется подключаться: сертификат выписан на домен.

Продление сертификата автоматическое (cron acme.sh); при продлении панель перезапускается сама, потому что сервер подписок читает сертификат только при старте. `vpn check` показывает срок сертификата и проверяет подписку по новому адресу. При повторном `vpn reality self` короткая ссылка сохраняется. На ноде команда недоступна: подписки раздаёт главный сервер.

## 5. Сеть и обход блокировок

### `vpn reality` — маскировка Reality

Reality маскирует VLESS под TLS-соединение с настоящим сайтом (target и SNI). От этого выбора зависит, работает ли VLESS из России. SNI крупных CDN (Cloudflare, Google, Amazon, Microsoft…) на чужом IP ТСПУ режет. Сайт из сети того же хостера работает лучше, но и он может периодически резаться: SNI не совпадает с IP сервера. Надёжнее всего **свой домен** (`vpn reality self`, ниже).

```
vpn reality [self <домен> | auto | <домен> | <ip:443> <домен>] [--force]
```

```
vpn reality                              # текущие SNI и target
vpn reality auto                         # найти сайт в сети хостера и переключиться
vpn reality www.example.com              # свой сайт (target = он же, порт 443)
vpn reality 213.165.59.85:443 site.ru    # target по IP, SNI = домен
vpn reality bad.example.com --force      # применить, даже если проверка не прошла
```

- **`auto`** перебирает соседние IP сервера (своя /24 и две соседние, около 1–3 минут), берёт домены из их сертификатов, проверяет TLS 1.3, HTTP/2 и X25519 и выбирает самый быстрый. Домены CDN он пропускает. Найденные варианты показывает, применяет лучший.
- Свой домен проверяется перед применением. Если он не подходит, утилита скажет почему и ничего не поменяет (если не указан `--force`).
- Применяется к обоим Reality-серверам (TCP и XHTTP). Ключи, shortId и пользователи сохраняются.
- **После смены клиентам нужно обновить подписку**, потому что SNI в ссылке меняется.
- Если сайт-маскировка упадёт или сменит сертификат, `vpn check` покажет `[FAIL]`. Тогда просто снова `vpn reality auto`.

#### `vpn reality self` — Reality на свой домен

```
vpn reality self fi.example.xyz
```

Так делают коммерческие сервисы. SNI — твой собственный домен, который указывает на IP этого сервера. Маскировкой служит маленький сайт на самом сервере с настоящим сертификатом Let's Encrypt. Имя в рукопожатии совпадает с адресом, поэтому у ТСПУ нет признака «Reality на чужом IP». Кто откроет `https://fi.example.xyz` в браузере, увидит обычную страницу с действительным сертификатом.

Что нужно заранее:
1. Купить домен. Подойдёт любой дешёвый (.xyz, .space, .site…), имя без слов vpn/proxy. Не бери .ru/.рф: домен в российской зоне могут снять с делегирования.
2. У регистратора создать **A-запись** для поддомена (например, `fi`) → IP сервера. **AAAA-запись не добавлять.**
3. Подождать 5–15 минут и проверить: `getent hosts fi.example.xyz` должен показать IP сервера.
4. Порт 80/tcp должен быть открыт у хостера. Он нужен Let's Encrypt для выпуска и продления сертификата, установщик его уже открыл.

Что делает команда:
- проверяет, что A-запись указывает на этот сервер, и предупреждает о лишних A/AAAA;
- выпускает сертификат через acme.sh и ставит автопродление (тот же cron, что у сертификата панели);
- ставит nginx и поднимает сайт-заглушку только на `127.0.0.1` (наружу nginx не открыт, 80/tcp не занимает);
- проверяет, что сайт отвечает по TLS с действительным сертификатом и HTTP/2;
- переключает VLESS TCP и XHTTP: SNI = домен, target = локальный сайт. Ключи и пользователи сохраняются.

**После этого клиентам нужно обновить подписку.** Hysteria2 не меняется.

`vpn check` для такой схемы проверяет A-запись, локальный сайт (TLS, сертификат, HTTP/2) и сколько дней осталось сертификату. Повторный запуск `vpn reality self <домен>` безопасен: например, после смены домена или если что-то сломалось. Вернуться на чужой сайт можно через `vpn reality auto`, nginx при этом можно оставить.

> **HTTP3 и домен.** Сервер HTTP3 можно выбрать и при установке (`PROTOCOLS=…,http3` или пункт 4 в меню), но только вместе со своим доменом (`SELF_DOMAIN=cdn.example.com`, A-запись → сервер) и ещё одним Reality-сервером (VLESS TCP или XHTTP). Скрипт сам выполнит `vpn reality self` и `vpn http3 on`. Без домена HTTP3 не работает, его можно включить и позже.
>
> **Если при установке выбраны не все серверы.** Команды работают с тем, что есть. Reality-команды (`vpn reality`, `vpn reality self`, `vpn http3`) нужны серверу VLESS TCP или XHTTP; если создан только Hysteria2, `vpn xhttp on` добавит сервер с Reality. `vpn hop` работает только при Hysteria2. «⚡ Лучший сервер» появляется, когда серверов два и больше (`vpn fastest on`).

### `vpn xhttp` — сервер VLESS XHTTP

Дополнительный сервер VLESS + XHTTP + Reality на отдельном TCP-порту. Изнутри похож на обычный HTTP/2-трафик браузера и лучше переносит «заморозку» TCP-соединений на ТСПУ.

```
vpn xhttp                 # статус
vpn xhttp on              # включить на порту 8443
vpn xhttp on 2083         # на своём порту
vpn xhttp off             # выключить
```

- При включении все существующие пользователи сразу на него добавляются, новые (`vpn add`) — автоматически. Порт открывается в ufw.
- Использует ту же маскировку Reality, что и VLESS TCP, но со своими ключами.
- Название по умолчанию: имя VLESS-сервера без «VLESS …» + « VLESS XHTTP» (например, «🇫🇮 VLESS XHTTP»). Поменять можно через `vpn brand --xhttp-name`.
- При выключении пользователи отвязываются аккуратно, их трафик и лимиты сохраняются.
- **Клиенты на sing-box** (Hiddify, Podkop, Tachyon) XHTTP не поддерживают и просто не показывают этот сервер.
- Если у хостера свой фаервол, откройте в нём порт. Затем обновите подписку в клиентах.

### `vpn http3` — сервер HTTP3 (VLESS XHTTP по HTTP/3, QUIC/UDP)

Ещё один сервер VLESS + XHTTP, но поверх **HTTP/3 (QUIC, UDP)** и с обычным TLS на твоём домене, с настоящим сертификатом Let's Encrypt. Для DPI это выглядит как HTTP/3 к сайту `cdn.<твой домен>`. Нужен, когда ТСПУ глушит TCP к серверу, а UDP пропускает: тогда у клиентов на Xray (INCY, Happ, v2RayTun) остаётся второй UDP-путь, кроме Hysteria2.

```
vpn http3                                     # статус
vpn http3 on                                  # включить на 4443/udp
vpn http3 on 4443 --name "🇫🇮 VLESS XHTTP HTTP3"     # с портом и названием
vpn http3 off                                 # выключить
```

- **Сначала нужен свой домен:** `vpn reality self <домен>`. Сервер берёт его сертификат из `/etc/vpn/self/`. Xray сам перечитывает файл после автопродления (раз в час), перезапуск не нужен. При смене домена через `vpn reality self` SNI у сервера HTTP3 обновляется сам.
- Порт по умолчанию 4443/**udp**. Номер должен отличаться от портов других серверов, даже TCP: панель 3x-ui не даёт двум серверам один номер порта (поэтому не 8443 — там XHTTP). Порт открывается в ufw. Если у хостера свой фаервол, открой там этот UDP-порт.
- Все пользователи добавляются сразу, новые — автоматически. Сервер попадает в «⚡ Лучший сервер».
- Название по умолчанию: имя XHTTP-сервера + « HTTP3». Поменять: `vpn http3 on … --name` или `vpn brand --http3-name`.
- `vpn check` проверяет, что UDP-порт слушается, что в подписке есть ссылка с `alpn=h3`, и делает сквозной тест через QUIC.
- Работает в клиентах на ядре Xray: INCY, Happ, v2RayTun, v2rayN, а на роутерах — Passwall и другие сборки с Xray.
- *Пометка:* sing-box (Podkop, Hiddify) XHTTP не поддерживает. tachyon-core (Tachyon) на момент проверки (октябрь 2026) умеет XHTTP только поверх TCP. В них сервер HTTP3 будет n/a, это не ошибка сервера. Их UDP-вариант — Hysteria2.
- Если оператор режет весь QUIC/UDP (так бывает на мобильном интернете), HTTP3 упадёт вместе с Hysteria2. Тогда остаются TCP-варианты.

### `vpn hop` — port hopping для Hysteria2

Hysteria2 начинает принимать подключения на целом диапазоне UDP-портов, клиент прыгает между ними. Это обходит блокировку и душение по одному порту.

```
vpn hop                   # статус
vpn hop on                # диапазон UDP 20000-50000
vpn hop on 30000-40000    # свой диапазон (внутри 1025–65535)
vpn hop off               # выключить
```

- На сервере это правило iptables, которое заворачивает диапазон на 443. Оно живёт в сервисе `vpn-hop` и переживает перезагрузку. В ссылку Hysteria2 добавляется параметр `mport`.
- Клиенты, которые не умеют hopping, продолжают ходить на 443.
- ⚠️ **Tachyon (и, вероятно, другие роутерные клиенты на sing-box) с включённым hopping не запускается**: ошибка `outbounds[N]: missing server_port`. Если у вас или пользователей такие роутеры, держите hopping выключенным.
- Если у хостера свой фаервол, откройте в нём UDP-диапазон. Затем обновите подписку в клиентах.

### `vpn fastest` — сервер «Лучший сервер»

Добавляет в подписку первым пунктом сервер **«⚡ Лучший сервер»**. Это балансировщик Xray: он регулярно (по умолчанию примерно раз в 10 секунд) пингует все серверы (VLESS TCP, Hysteria2, VLESS XHTTP) через сам туннель и ведёт трафик через самый быстрый живой. Если один протокол зарежут, клиент сам перейдёт на другой.

```
vpn fastest                                   # статус: включён ли, сколько серверов внутри, каким клиентам
vpn fastest on                                # включить (при новой установке включается сам)
vpn fastest on --name "🚀 Авто"               # переименовать
vpn fastest on --clients happ,v2raytun,incy   # список клиентов, которым его отдавать
vpn fastest on --interval 10s --sampling 2 --timeout 4s   # как быстро он замечает упавший сервер
vpn fastest off                               # выключить
```

- **Как это устроено.** Обычные ссылки (`vless://`, `hysteria2://`) балансировщик описать не умеют, поэтому он отдаётся в JSON-подписке Xray. Ссылка подписки остаётся одна: сервер подписок смотрит на User-Agent клиента. Клиенты из списка (`--clients`, по умолчанию `happ,v2raytun,incy`) получают JSON: «Лучший сервер» плюс все серверы по отдельности. Остальные получают обычные ссылки.
- Если какой-то клиент из списка после обновления показывает пустой список серверов, значит, он не понимает JSON: уберите его, например `vpn fastest on --clients happ,v2raytun`.
- **Роутеры на sing-box** (Tachyon, Podkop) всегда получают обычные ссылки, у них свой url test.
- `--name` и `--clients` запоминаются: повторный `vpn fastest on` без флагов их не сбрасывает (кроме названия после `off`).
- **Как быстро он переключается.** Клиент проверяет серверы по трём параметрам (`vpn fastest status` показывает текущие):

  | Параметр | Что значит | По умолчанию |
  | --- | --- | --- |
  | `--interval` | в среднем как часто проверяется каждый сервер. Меньше 10s Xray не принимает | `10s` |
  | `--sampling` | сколько последних проверок помнить. Цикл проверок = `interval × sampling` | `2` |
  | `--timeout` | сколько ждать ответа, прежде чем считать проверку неудачной | `4s` |

  Упавший сервер снимается с выбора после **одного-двух циклов** подряд неудачных проверок, то есть через `interval × sampling` … `interval × sampling × 2`. При 10s и 2 это 20–40 секунд (раньше стояло 30s и 2: 60–120 секунд, отсюда долгое переключение). Меньше `sampling` и `interval` — быстрее реакция, но больше проверок и больше риск ложных срабатываний на плохой сети (одна потерянная проверка может увести трафик на другой сервер). Больше `timeout` — меньше ложных срабатываний на медленных каналах (например, Hysteria2 по мобильной сети), но реакция медленнее. Значения запоминаются. Соединения, которые уже были открыты через упавший сервер, зависнут до обрыва, а новые пойдут через живой.
- На роутерах (Tachyon, Podkop) «Лучший сервер» не работает: они получают обычные ссылки и переключаются по своему url test, его интервал настраивается в самом роутере.
- При `vpn xhttp on/off` состав балансировщика обновляется сам.
- После `on`/`off` панель перезапускается (VPN моргнёт на пару секунд). Затем обновите подписку в клиентах.
- `vpn check` проверяет, что JSON-подписка отдаёт «Лучший сервер», что у VLESS в JSON правильный `encryption`, и делает сквозной тест через балансировщик.

## 5а. Несколько серверов: ноды

Другие серверы подключаются к главному как **ноды** (режим нод 3x-ui v3.9+). Пользователи, лимиты, трафик и подписка живут на главном сервере, а серверы нод появляются у всех в той же подписке и в «⚡ Самом быстром».

### `vpn node prepare` — на новом сервере

```
vpn node prepare          # удалить локальных пользователей, стать нодой, показать команду для главного
vpn node prepare --yes    # то же без вопроса
```

- Удаляет пользователей этого сервера. Иначе их имена (`me`, `healthcheck`) совпадут с пользователями главной панели и испортят им подписки.
- Выключает здесь «Лучший сервер»: подписку отдаёт главный сервер.
- Создаёт API-токен `master` и печатает готовую команду `vpn node add …`. Повторный запуск выпускает новый токен, старый перестаёт работать.
- Установщик с `NODE=1` делает всё это сам и сохраняет команду в `/etc/vpn/node-add.txt`.
- На ноде после этого отключены `vpn add`, `renew`, `reset`, `off/on`, `del`, `limit`, `devices`, `fastest`. Работают `brand` (названия серверов), `reality`, `xhttp`, `http3`, `hop`, `check`, `trace`.

### `vpn node add` — на главном сервере

```
vpn node add https://203.0.113.5:23456/AbCdEf/ ТОКЕН --name nl-1
```

1. Проверяет API ноды и что на ней нет своих пользователей (если есть — просит `vpn node prepare`).
2. Проверяет, что главная панель достучится до ноды, и регистрирует её. Если сертификат панели ноды не проходит проверку, подключает без неё и предупреждает.
3. Ждёт, пока главная панель подтянет серверы ноды, добавляет на них **всех** пользователей и включает их в «Лучший сервер».

После этого пользователям достаточно обновить подписку.

### `vpn node`, `vpn node sync`, `vpn node del`

```
vpn node              # список: имя, адрес, в сети ли, задержка, серверы каждой ноды
vpn node sync         # после vpn xhttp/http3 on на ноде: добавить новые серверы ноды в подписку всем пользователям
vpn node del nl-1     # отключить ноду
```

- `del` снимает пользователей с серверов ноды, убирает их из подписки и «Самого быстрого» и удаляет регистрацию ноды. **Саму ноду не трогает**: её 3x-ui и серверы остаются. Подключить снова: на ноде `vpn node prepare`, на главном — новая команда `vpn node add`.
- Названия серверов ноды и её маскировку меняй на самой ноде (`vpn brand`, `vpn reality self`). Главная панель подхватывает изменения сама.
- `vpn check` на главном показывает раздел «Ноды» (в сети ли, все ли серверы нод подключены к пользователям) и делает сквозной тест через каждый сервер ноды.

## 5б. Переезд на другой сервер

Новый сервер становится главным, старый остаётся до конца аренды. Пользователи, ключи, ссылки подписок, сроки, лимиты и трафик переносятся командами `export` и `import`. Пошаговый план с DNS: [README, раздел 14а](../README.md#14а-переезд-на-новый-сервер).

### `vpn export` — выгрузить пользователей (на старом сервере)

```
vpn export /root/vpn-clients.json
```

- Пишет JSON с пользователями и настройками подписки в файл (права 600). Без файла команда на терминале откажется: в выгрузке ключи пользователей.
- Служебный пользователь `healthcheck` не выгружается.
- Нужна свежая версия `vpn`: `bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh) --cli` (сервер и пользователи не затрагиваются).
- После переноса удалите файл: `rm /root/vpn-clients.json`.

### `vpn import` — принять пользователей (на новом сервере)

```
vpn import --from root@203.0.113.7            # забрать данные по ssh (спросит пароль root старого сервера)
vpn import --from root@203.0.113.7:2222       # ssh на нестандартном порту
vpn import /root/vpn-clients.json             # из файла
vpn import --from root@203.0.113.7 --update   # повторный прогон: обновить уже перенесённых
```

| Параметр | Что делает |
| --- | --- |
| `--from [user@]хост[:порт]` | выполняет на старом сервере `vpn export` по ssh и берёт данные оттуда (по умолчанию `root`, порт 22) |
| `--update` | пользователей, которые уже есть здесь, перезаписывает данными со старого сервера: срок, лимиты, включён/отключён, ключи, израсходованный трафик. Без него такие пользователи пропускаются, а новые создаются |
| `--no-links` | не менять порт и путь подписки (по умолчанию они берутся со старого сервера, чтобы прежние ссылки заработали) |
| `--no-brand` | не копировать подпись подписки (название, описание, поддержка, кнопка сайта) |
| `--yes` | без вопроса «Перенести?» (в скриптах и без терминала обязателен) |

Что делает:
1. Показывает, сколько пользователей будет создано, обновлено и пропущено, и спрашивает подтверждение.
2. Создаёт пользователей с теми же UUID, ключами Hysteria2, ID подписки, лимитами, сроком и израсходованным трафиком и подключает их ко всем серверам этой панели. Пользователь `me` (его создал установщик) заменяется старым, чтобы осталась прежняя ссылка владельца.
3. Если порт или путь подписки отличаются, ставит как на старом сервере, перезапускает панель (VPN моргнёт на пару секунд), открывает порт в `ufw` и проверяет, что подписка отдаётся. Если проверка не прошла, возвращает прежние настройки (пользователи остаются перенесёнными). Если порт со старого сервера занят здесь, предупреждает и ничего не меняет.
4. Копирует подпись подписки и лимиты по умолчанию.
5. Печатает, что делать дальше: переключить A-запись домена, `vpn reality self`, `vpn sub-domain`, `vpn http3 on` и что ещё было включено на старом сервере.

Важно:
- **Идемпотентно:** повторный запуск без `--update` ничего не ломает, уже перенесённые пользователи пропускаются. Перед самим переключением DNS запустите с `--update`, чтобы подтянуть продления и новых пользователей, которые появились на старом сервере.
- **Не переносится:** ключи Reality и сертификаты (на новом сервере свои, клиент получит их из подписки), названия серверов, протоколы и порты, устройства (HWID регистрируются заново), ноды, Telegram-бот, пароль панели.
- **Ссылки подписки на домене** (`vpn sub-domain`) после переключения DNS продолжают работать. Ссылки на IP старого сервера перенести нельзя, пользователям нужна новая (`vpn link <имя>`).
- Трафик, потраченный пользователями через старый сервер после последнего `--update`, на новом не учитывается.
- Команды доступны только на главном сервере, не на ноде.

## 6. Диагностика

### `vpn check` — проверить всё

```
vpn check            # полная проверка, включая доступность снаружи (около минуты)
vpn check --local    # без внешней проверки (быстрее)
```

Что проверяется:

| Блок | Проверки |
| --- | --- |
| Сервисы | запущен ли x-ui, отвечает ли API, работает ли Xray и какой версии |
| Порты на сервере | слушаются ли 443/tcp, 443/udp, порт панели, порт подписок, порт XHTTP. Есть ли правило port hopping. Открыты ли нужные порты в ufw. Работает ли fail2ban (если у кого-то есть лимит IP) |
| Система | синхронизировано ли время, включён ли BBR, хватает ли диска и памяти |
| Сертификат | сколько ещё действует, есть ли автопродление, проходит ли TLS подписок проверку сертификата |
| Подписка и маскировка | отдаёт ли подписка все серверы, есть ли `mport` при hopping. Отдаёт ли JSON-подписка «Лучший сервер» (если включён). Подходит ли сайт-маскировка (TLS 1.3, h2, X25519). Не крупный ли это CDN |
| Сквозной тест | на сервере поднимается настоящий клиент Xray, подключается по **каждому** протоколу (и через «Лучший сервер») и выходит через VPN в интернет. Показывается IP выхода |
| Снаружи (без `--local`) | доступны ли порты 443, XHTTP, подписок, панели и 80 с узлов check-host.net в России и в Европе |

Каждая строка помечена `[OK]`, `[WARN]` (работает, но обратите внимание) или `[FAIL]` (не работает, рядом написано, что делать). В конце итог. Код возврата ненулевой, если есть `[FAIL]`, поэтому команду можно ставить в cron или скрипты.

Как читать типичные результаты:
- **Сквозной тест `[OK]`, а у пользователя не работает.** Сервер исправен, проблема на пути до него (провайдер, ТСПУ) или в клиенте.
- **`недоступен из России, из Европы доступен`.** Похоже на блокировку IP в РФ.
- **`80/tcp доступен` при том, что на нём ничего не слушает.** Это нормально: порт нужен только в момент продления сертификата.
- UDP (Hysteria2, hopping) снаружи проверить нельзя. Его работу подтверждает сквозной тест и клиент на телефоне.

**Мониторинг, когда «то работает, то нет».** Сервер каждые 15 секунд проверяет сам себя, пока вы смотрите на клиент:

```bash
for i in $(seq 40); do printf '%s  ' "$(date +%T)"; vpn check --local 2>&1 | sed 's/\x1b\[[0-9;]*m//g' | grep -E 'работает,|не смог' | awk '{printf "%s %s  ", $1, $2}'; echo; sleep 15; done
```

Если в моменты сбоя у клиента на сервере всё `[OK]`, проблема не в сервере.

### `vpn trace` — что происходит с подключениями клиента

Когда `vpn check` весь зелёный, а у клиента серверы то и дело `n/a`, нужно понять, доходят ли его подключения до сервера и что с ними дальше. `vpn trace` записывает подключения на порты VPN (443/tcp, XHTTP, 443/udp и диапазон hopping), а в конце разбирает каждое.

```bash
vpn trace                         # все клиенты, 120 секунд
vpn trace 109.252.152.126         # только этот IP
vpn trace 109.252.152.126 300     # 5 минут
```

Пока идёт запись, нажимайте в клиенте проверку пинга и запоминайте время, когда серверы были `n/a`. Новые подключения появляются на экране сразу. Закончить раньше можно через Ctrl+C, разбор всё равно будет показан. Свой IP клиент может посмотреть на 2ip.ru с выключенным VPN.

Пример разбора:

```
  время    прот порт  клиент                    сек       к серверу      от сервера  повт  итог
  15:58:51 tcp  443   109.252.152.126:51234     0.3     11п    1.8K     10п    6.9K   0/0  ok
  15:59:22 tcp  8443  109.252.152.126:51240     4.0      4п    517B      9п    7.7K   5/0  ОТВЕТЫ НЕ ДОХОДЯТ ДО КЛИЕНТА (повторы сервера)
  15:59:23 udp  443   109.252.152.126:40000     0.0      3п    3.6K      0п      0B   0/0  СЕРВЕР НЕ ОТВЕТИЛ
```

Колонки: сколько пакетов и байт пришло от клиента и ушло от сервера. «повт» — повторные отправки сервера / клиента.

| Итог | Что значит |
| --- | --- |
| Подключение не появилось вовсе | до сервера ничего не дошло: блокировка или потеря по пути (оператор, ТСПУ), либо клиент сам не подключался |
| `ok` | сервер ответил, обмен данными был. Если клиент при этом показывал `n/a`, дело не в сети до сервера: смотрите тайм-аут теста в клиенте или туннель роутера |
| `СЕРВЕР НЕ ОТВЕТИЛ` | пакеты пришли, ответа нет: проверьте `vpn check` и `systemctl status x-ui` |
| `ОТВЕТЫ НЕ ДОХОДЯТ ДО КЛИЕНТА` | сервер отвечает, но повторяет отправку: ответы теряются на обратном пути. Типичная картина «заморозки» соединений к зарубежным IP |
| `клиент оборвал на рукопожатии TLS` | клиент разорвал подключение сразу после начала TLS. Бывает, когда рукопожатие портит DPI или обход блокировок на роутере (zapret) |
| `порт закрыт` | на этом порту ничего не слушает |

Запись сохраняется в `/tmp/vpn-trace.*.pcap`. Её можно открыть в Wireshark или удалить. Пока идёт запись, не качайте ничего тяжёлого через VPN: файл ограничен 500 000 пакетов.

## 7. Обслуживание самой утилиты

### Обновление

Обновляет только утилиту `vpn` до версии из репозитория. Сервер, пользователи и настройки не затрагиваются:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/p0sixxx/3x-ui-autodeploy/main/vpn-setup.sh) --cli
```

### Файлы

| Файл | Что внутри |
| --- | --- |
| `/usr/local/bin/vpn` | сама утилита |
| `/etc/vpn/vpn.env` | настройки утилиты: адрес API, токен, id серверов, порты, лимиты по умолчанию (`DEF_DEVICES`, `DEF_IPS`), `XHTTP_PORT`, `HOP_PORTS`, `FASTEST_ID`, `FASTEST_CLIENTS` |
| `/etc/vpn/panel.txt` | адрес, логин и пароль панели |
| `/etc/vpn/check-install.txt` | отчёт проверки при установке |
| `/etc/systemd/system/vpn-hop.service` | port hopping (если включён) |

Все файлы в `/etc/vpn/` доступны только root. Не передавайте их никому: токен даёт полный доступ к панели.

### Если `vpn` пишет «токен недействителен»

Утилита работает через API-токен `vpn-cli`. Если его перевыпустили (в панели или командой `x-ui setting -getApiToken -tokenName vpn-cli`), старый перестаёт работать. Починка:

```bash
T=$(/usr/local/x-ui/x-ui setting -getApiToken -tokenName vpn-cli | grep -Eo 'apiToken: .+' | awk '{print $2}')
sed -i "s|^TOKEN=.*|TOKEN='$T'|" /etc/vpn/vpn.env && vpn list
```

Если ошибка «панель не ответила», сначала проверьте, что панель запущена: `systemctl restart x-ui`.

### Ошибки и коды возврата

- Ошибки печатаются как `Ошибка: …` (текст от панели) или как подсказка по аргументам. Код возврата при этом `1`.
- Команды не интерактивны, кроме мастера `vpn brand` без флагов. Их можно вызывать из своих скриптов, например из Telegram-бота для приёма оплаты: `vpn add`, `vpn renew`, `vpn link`.

### Служебные команды

`vpn _probe`, `vpn _scan`, `vpn _country`, `vpn _hop` вызываются самой утилитой и установщиком. Запускать их вручную не нужно.

## 8. Шпаргалка

| Команда | Что делает |
| --- | --- |
| `vpn add <имя> <ГБ> <дней> [коммент] [--devices N] [--ips N]` | новый пользователь, ссылка и QR |
| `vpn link <имя>` | ссылка подписки и QR |
| `vpn list` | все пользователи |
| `vpn renew <имя> <дней> [ГБ]` | продлить (дни к текущему сроку) и обнулить трафик |
| `vpn expire <имя> <дней>` | задать срок «N дней от сегодня» (0 — бессрочно), трафик не трогает |
| `vpn reset <имя>` | обнулить трафик |
| `vpn off <имя>` / `vpn on <имя>` | отключить / включить |
| `vpn del <имя>` | удалить насовсем |
| `vpn panel` | адрес панели (с секретным путём), логин и пароль; показывает их в любое время |
| `vpn panel hide` / `show` / `status` | закрыть панель снаружи (только 127.0.0.1, доступ через ssh-туннель) / открыть / состояние |
| `vpn limit <имя\|all\|default> [--devices N] [--ips N]` | лимиты устройств и IP |
| `vpn devices <имя> [reset\|<номер>]` | устройства пользователя |
| `vpn brand [флаги]` | подпись подписки и названия серверов |
| `vpn reality [auto\|<домен>\|<ip:443> <домен>]` | маскировка Reality |
| `vpn reality self <свой домен>` | Reality на свой домен (самая устойчивая к блокировкам) |
| `vpn sub-domain <домен> [--port]` / `off` / `status` | ссылка подписки на своём домене: `https://домен/<ID>` вместо IP с портом |
| `vpn xhttp [on [порт]\|off]` | сервер VLESS XHTTP |
| `vpn http3 [on [порт] [--name Т]\|off]` | сервер HTTP3: VLESS XHTTP по HTTP/3 (QUIC, UDP) на своём домене |
| `vpn hop [on [от-до]\|off]` | port hopping для Hysteria2 |
| `vpn fastest [on\|off] [--name Т] [--clients …]` | сервер «⚡ Лучший сервер» |
| `vpn check [--local]` | диагностика |
| `vpn node [add <адрес> <токен> [--name имя] \| sync \| del <имя> \| prepare]` | ноды: несколько серверов в одной подписке |
| `vpn export [файл]` | (на старом сервере) выгрузить пользователей и настройки подписки в файл |
| `vpn import <файл>\|--from [user@]хост[:порт] [--update] [--no-links] [--no-brand] [--yes]` | (на новом сервере) принять пользователей: те же ссылки подписок, сроки, лимиты и трафик |
| `vpn trace [IP] [секунд]` | запись и разбор подключений клиента |
| `vpn help` | справка |
